# Feature 01. 즉시 입력 가능한 다중 문서 창

## 1. Idea Summary

앱을 실행하면 별도 홈 화면이나 최근 문서 선택 없이 곧바로 빈 plain text 문서 창 하나가 열리고, 커서가 이미 활성화된 상태에서 즉시 타이핑을 시작할 수 있게 하는 기능이다. 사용자는 필요할 때 새 문서를 추가로 열거나 Finder 또는 파일 열기로 기존 `.txt` 파일을 별도 창에서 열어 각 창에서 서로 다른 메모를 병렬로 작성할 수 있고, 각 창은 자신의 제목, 저장 경로, 미저장 상태를 독립적으로 가진다.

## 2. Problem This Feature Solves

- 메모장 앱의 핵심 가치는 `실행 즉시 적는다`는 반응 속도다.
- 대시보드, 문서 선택 화면, 빈 상태 안내는 첫 입력을 늦춰 메모 손실 가능성을 높인다.
- 단일 창만 허용하면 짧은 메모를 병렬로 분리하는 기본적인 메모장 사용 패턴을 지원하지 못한다.
- 저장과 종료 플로우도 먼저 문서 입력이 자연스럽게 시작되어야 의미가 생긴다.

## 3. Target User and Usage Context

- 회의 중 짧은 문장이나 숫자를 빠르게 적고 싶은 사용자
- 다른 주제의 메모를 창 단위로 분리해 두고 번갈아 작성하려는 사용자
- 서식 없는 텍스트를 바로 다른 도구로 옮겨야 하는 개발자, 기획자, 사무직 사용자
- 앱을 열었을 때 무엇을 눌러야 할지 고민하지 않고 즉시 입력을 기대하는 사용자

## 4. Feature Concept Definition

### Feature name

즉시 입력 가능한 다중 문서 창

### One-sentence definition

앱 시작, 새 문서 생성, 기존 `.txt` 파일 열기 시 즉시 포커스를 가진 독립적인 plain text 문서 창을 생성하고 창별 편집 상태를 분리해 유지하는 기능이다.

### Why it matters

- 이 기능이 없으면 제품의 차별점인 즉시성 자체가 무너진다.
- 이후 저장, 닫기 확인, undo/redo, word wrap 같은 모든 편집 기능이 이 문서 세션 단위를 기준으로 동작해야 한다.
- 다중 창 지원은 `메모 앱`이 아니라 `메모장`에 가까운 작업 흐름을 만든다.

### Who uses it and when

- 앱 첫 실행 시 모든 사용자
- 이미 하나의 문서를 작성 중이지만 별도 메모를 바로 열고 싶은 사용자
- 저장 여부와 무관하게 빠르게 새 텍스트 세션을 추가하려는 사용자

### MVP relevance

- 우선순위: P0
- 이 기능이 완성되지 않으면 나머지 MVP 기능의 사용성 검증이 왜곡된다.
- 첫 실행 후 3초 안에 입력 가능 상태에 도달하는 경험이 핵심 성공 조건이다.

### Confirmed requirements

- 앱 첫 진입 시 빈 문서 1개를 연다.
- 사용자는 새 문서를 추가로 열어 여러 문서 창을 독립적으로 사용할 수 있다.
- 사용자는 Finder 또는 파일 열기로 기존 `.txt` 파일을 각자의 독립 창에서 열 수 있다.
- 편집기는 plain text 전용이다.
- 창이 열리면 텍스트 입력 포커스를 자동으로 가진다.
- 사용자는 키보드 입력과 plain text 붙여넣기를 할 수 있다.
- 내용이 변경되면 문서는 미저장 상태가 된다.
- 미저장 상태는 창 제목 뒤의 `*` 표시로 노출된다.

### Assumptions to keep MVP narrow

- 탭 기반 다중 문서 UI는 제공하지 않는다.
- 최근 문서, 세션 복구, 자동 복원은 제공하지 않는다.
- 저장 전 기본 문서명은 `Untitled`, `Untitled 2`, `Untitled 3`처럼 순번을 붙여 구분한다.
- 기존 `.txt` 파일 열기는 지원하되, 최근 문서 목록이나 자동 복원은 제공하지 않는다.

## 5. Main User Flow and Interaction Model

### Flow A. 앱 실행, 재실행, 무창 상태 재활성화

1. 사용자가 앱을 실행한다.
2. 앱은 별도 홈 화면 없이 빈 문서 창 1개를 즉시 생성한다.
3. 편집 영역이 화면에 표시되고 커서가 자동으로 활성화된다.
4. 사용자가 첫 키 입력을 수행하면 해당 창의 문서 내용이 갱신된다.
5. 첫 변경이 발생하면 문서는 미저장 상태로 전환되고 제목 뒤에 `*`가 표시된다.
6. 사용자가 모든 창을 닫은 뒤 앱을 다시 활성화하면 앱은 새 빈 문서 창을 자동으로 다시 연다.

### Flow B. 새 문서 추가

1. 사용자가 메뉴에서 새 문서 액션을 실행한다.
2. 앱은 기존 창과 별개의 새 빈 문서 창을 생성한다.
3. 새 창은 자신의 편집 상태, 저장 경로, 제목을 독립적으로 가진다.
4. 새 창의 편집기에 포커스가 자동으로 이동한다.
5. 기존 창의 내용과 저장 상태는 변경되지 않는다.

### Flow C. 텍스트 입력과 붙여넣기

1. 사용자가 현재 활성 창에서 키보드 입력, 삭제, 개행, 붙여넣기를 수행한다.
2. 앱은 입력 내용을 현재 창 문서에만 반영한다.
3. 붙여넣기 데이터에 서식이 포함되어 있어도 plain text만 남긴다.
4. 입력 결과는 즉시 화면에 반영된다.
5. 저장 완료 상태였던 문서가 다시 변경되면 다시 미저장 상태가 된다.

### Flow D. 여러 창 병렬 사용

1. 사용자가 두 개 이상의 문서를 열어둔다.
2. 각 창은 제목, 현재 텍스트, 저장 경로, 미저장 상태를 독립적으로 유지한다.
3. 사용자가 한 창을 닫거나 저장해도 다른 창의 상태는 바뀌지 않는다.
4. 메뉴 기반 편집 액션은 항상 활성 창 기준으로만 적용된다.

### Flow E. 기존 `.txt` 파일 열기

1. 사용자가 Finder에서 `.txt` 파일을 열거나 앱의 파일 열기 액션을 실행한다.
2. 앱은 선택된 파일을 새로운 문서 창으로 연다.
3. 창 제목은 해당 파일명을 표시한다.
4. 파일 내용은 plain text 그대로 편집 영역에 로드된다.
5. 파일을 연 직후에는 미저장 변경이 없는 상태로 시작한다.
6. 이후 편집, 저장, 닫기 판단은 다른 문서 창과 동일한 규칙을 따른다.

## 6. Inputs, Outputs, and States

### Inputs

- 앱 실행
- 앱 재실행
- 창이 없는 상태의 앱 재활성화
- 새 문서 생성 액션
- Finder에서 `.txt` 파일 열기
- 파일 열기 액션과 선택된 `.txt` 파일 경로
- 키보드 문자 입력
- 삭제, 개행, 커서 이동
- plain text 붙여넣기
- 창 전환
- 창 닫기 직전의 현재 조합 문자 확정 이벤트

### Outputs

- 즉시 편집 가능한 빈 문서 창
- 파일 내용을 로드한 기존 문서 창
- 현재 창에 표시되는 plain text 내용
- 창 제목의 현재 문서명 또는 기본 문서명
- 창 제목 뒤의 `*` 미저장 표시
- 창별 독립 문서 상태

### Document session fields

- `textContent`: 현재 창의 plain text 본문
- `displayTitle`: 저장 파일명 또는 기본 문서명
- `filePath`: 저장 전에는 없고, 저장 후에는 현재 파일 경로
- `hasUnsavedChanges`: 마지막 저장 이후 변경 여부
- `isFocused`: 현재 편집 포커스 보유 여부
- `isIMEComposing`: 입력기 조합 중 여부
- `windowId`: 창 독립성 보장을 위한 식별자

### State definitions

| 상태                   | 설명                                                      | 진입 조건                         | 종료 조건                    |
| ---------------------- | --------------------------------------------------------- | --------------------------------- | ---------------------------- |
| 초기 빈 문서 상태      | 새 창이 열렸고 내용이 비어 있으며 입력 가능함             | 앱 실행 또는 새 문서 생성 직후    | 첫 편집 발생 또는 창 닫기    |
| 입력 중 상태           | 사용자가 현재 창에서 입력/붙여넣기를 수행 중임            | 포커스 있는 편집 창에서 입력 시작 | 포커스 이탈 또는 창 비활성화 |
| 미저장 변경 상태       | 마지막 저장 이후 현재 내용이 달라짐                       | 첫 변경 발생                      | 저장 성공                    |
| 저장 완료 상태         | 저장 경로가 있고 마지막 변경이 모두 반영됨                | 저장 성공                         | 다음 변경 발생               |
| 다중 창 동시 편집 상태 | 둘 이상의 문서 창이 열려 있으며 각 창이 독립적으로 유지됨 | 두 번째 창 이상 생성              | 창 수가 1개 이하로 줄어듦    |

### Title rules

- 저장 전 문서는 `Untitled`, `Untitled 2`, `Untitled 3` 규칙의 기본 문서명을 표시한다.
- 저장 후 문서는 현재 파일명을 표시한다.
- 미저장 변경이 있으면 제목 뒤에 `*`를 표시한다.
- 같은 시점에 열린 여러 창의 제목은 사용자가 서로 구분할 수 있어야 한다.
- 저장 직후에는 `*`가 제거되고 최신 제목 상태가 즉시 반영되어야 한다.

## 7. Business Rules

- 앱은 시작 시 별도 홈 화면을 두지 않는다.
- 사용자가 모든 창을 닫은 뒤 앱만 살아 있는 상태에서 다시 앱을 활성화하면 새 빈 문서 창을 자동으로 연다.
- 새 문서 액션은 항상 새로운 빈 문서 창을 연다.
- Finder 또는 파일 열기로 기존 `.txt` 파일을 열면 해당 파일은 자신의 문서 창에서 독립적으로 열린다.
- 각 문서 창은 내용, 저장 경로, 미저장 상태, undo/redo 이력을 독립적으로 가진다.
- 편집기는 plain text만 취급한다.
- 서식 포함 붙여넣기는 서식 없이 텍스트만 남긴다.
- 공백, 탭, 줄바꿈, 일반 문자는 모두 편집 내용으로 반영한다.
- 종료 분기에서는 공백, 탭, 줄바꿈만 있는 내용을 빈 문서로 간주한다.
- 메뉴 기반 저장, 실행 취소, 다시 실행, 보기 설정 액션은 활성 창 기준으로 적용한다.
- 한글 입력기 조합 중 종료 또는 포커스 이동이 발생하면 현재 조합 문자를 안전하게 반영한 뒤 다음 분기로 진행한다.
- 한 창을 닫아도 다른 창은 열린 상태와 편집 내용을 유지한다.

## 8. Validation and Error Handling

- 앱 실행 직후 첫 키 입력이 누락되면 안 된다.
- Finder 또는 파일 열기로 연 `.txt` 파일은 별도 창에서 올바른 텍스트 내용으로 로드돼야 한다.
- 입력 중 텍스트 손실이 발생하면 안 된다.
- 입력기 조합 중인 문자가 중복 삽입되거나 깨지면 안 된다.
- 붙여넣기 데이터에 제어 문자가 포함되어도 앱이 종료되면 안 된다.
- 한 창에서 발생한 입력이나 저장 상태 변화가 다른 창 문서에 반영되면 안 된다.
- 새 창 생성 직후 포커스가 편집기가 아닌 다른 UI에 머물면 안 된다.
- 저장 후 제목과 미저장 표시가 즉시 갱신되어야 한다.

## 9. Edge Cases and Resolved Decisions

### Edge cases

- 매우 긴 텍스트 붙여넣기는 허용하되, 대용량 편집기 수준의 최적화는 MVP 범위에 포함하지 않는다.
- 이미 저장된 문서에서 모든 내용을 지워 공백, 탭, 줄바꿈만 남은 상태가 되면 종료 시 빈 문서 판정 규칙을 따른다.
- 여러 창 중 하나에서만 입력기 조합 중일 때 다른 창 전환이 발생해도 조합 상태가 섞이면 안 된다.
- 저장되지 않은 여러 창이 동시에 존재할 때도 각 창의 미저장 표시가 정확해야 한다.

### Resolved decisions

- 저장 전 기본 문서명은 `Untitled`, `Untitled 2`, `Untitled 3`처럼 순번을 붙여 구분한다.
- 사용자가 모든 창을 닫은 뒤 앱만 살아 있는 상태에서 Dock 또는 앱 메뉴로 앱을 재활성화하면 새 빈 문서 창을 자동으로 다시 연다.
- 미저장 표시 `*`는 문서명 뒤에 suffix로 표시한다.

## 10. Product Implications and Dependencies

- [Feature 03. `.txt` 저장과 다른 이름으로 저장](./feature-03-txt-save.md)의 저장 상태 관리와 직접 연결된다.
- [Feature 04. 닫기 시 저장 확인 플로우](./feature-04-close-confirmation.md)의 종료 판정 기준은 이 기능의 텍스트 상태와 미저장 상태를 사용한다.
- [Feature 05. Undo/Redo](./feature-05-undo-redo.md)의 편집 히스토리는 창별 document session에 귀속되어야 한다.
- [Feature 06. Auto word wrap](./feature-06-auto-word-wrap.md)의 보기 상태는 현재 창 단위로 반영되어야 한다.
- 구현 관점에서는 `창 하나 = 문서 세션 하나` 모델이 MVP에 가장 단순하다.
- 포커스 자동 부여, IME 조합 처리, 창별 미저장 변경 여부 반영은 이후 저장/종료 기능보다 먼저 검증해야 하는 선행 조건이다.

## 11. Recommendation and Next Decision

### Recommendation

MVP에서는 `창 하나 = 문서 세션 하나` 원칙을 고정하는 것이 적절하다. 각 세션은 텍스트, 저장 경로, 미저장 여부, 포커스 상태를 독립적으로 가지며, 앱 시작과 새 문서 액션은 항상 즉시 입력 가능한 빈 창을 생성하는 방식으로 정의하는 것이 가장 단순하고 사용자 기대에도 부합한다.

### Next decisions

1. IME 조합 중 종료와 창 전환에 대한 QA 시나리오를 별도 체크리스트로 분리한다.

- 입력과 붙여넣기는 현재 활성 창에만 반영된다.
- 문서가 변경되면 제목 뒤에 `*`가 표시된다.
- 저장 성공 후 `*`가 제거되고 제목이 현재 파일명 기준으로 갱신된다.
- 한 창을 닫거나 저장해도 다른 창의 내용과 상태는 유지된다.
- 공백, 탭, 줄바꿈만 있는 문서의 종료 분기는 닫기 확인 기능의 판정 규칙과 일치한다.
- 앱에 열린 창이 하나도 없는 상태에서 사용자가 앱을 다시 활성화하면 새 빈 문서 창이 자동으로 열린다.

## 13. Out of Scope

- 여러 문서를 하나의 탭 스트립으로 묶는 UI
- Rich text 붙여넣기 유지
- 자동 복원과 세션 복구
- 최근 문서 목록
- 다중 창 레이아웃 저장
