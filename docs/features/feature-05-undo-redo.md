# Feature 05. Undo/Redo

## 1. Idea Summary

사용자가 현재 문서 창에서 발생한 텍스트 변경을 실행 취소와 다시 실행으로 되돌리거나 재적용할 수 있게 하는 기능이다. 이 기능은 plain text 편집기의 기본 신뢰 장치이며, 여러 문서 창을 동시에 열어 둔 상황에서도 편집 히스토리를 창별로 독립 유지하는 것을 전제로 한다.

## 2. Problem This Feature Solves

- 짧은 메모 편집에서도 삭제, 붙여넣기, 잘라내기, 대체 입력 실수는 자주 발생한다.
- undo/redo가 없으면 사용자는 작은 실수도 수동 복구해야 하므로 입력 흐름이 크게 끊긴다.
- 운영체제 기본 편집 경험을 기대하는 사용자는 `Command+Z`가 동작하지 않으면 앱을 불안정하거나 미완성으로 인식한다.
- 다중 창 환경에서 히스토리가 섞이면 복구 동작 자체가 위험해지므로 창 단위 독립성이 필수다.

## 3. Target User and Usage Context

- 회의 중 빠르게 메모를 작성하다가 직전 문장을 실수로 지운 사용자
- 여러 문서를 병렬로 열고 각 창에서 서로 다른 메모를 수정하는 사용자
- 한글 입력기 조합과 붙여넣기를 자주 사용하는 macOS 사용자
- 저장 전 단계에서 안전하게 수정과 복구를 반복하고 싶은 plain text 편집기 사용자

## 4. Feature Concept Definition

### Feature name

Undo/Redo

### One-sentence definition

현재 활성 문서 창의 텍스트 편집 히스토리를 기준으로 가장 최근 변경을 되돌리거나 다시 적용하는 창별 복구 기능이다.

### Why it matters

- 메모장 앱의 최소 편집 안전장치다.
- 저장 기능보다 앞서 사용자가 편집 실수를 안전하게 다룰 수 있어야 앱 신뢰도가 확보된다.
- 다중 창, 저장 상태, 닫기 확인 플로우 모두 현재 문서 상태를 기준으로 동작하므로 편집 히스토리 규칙을 먼저 고정해야 한다.

### Who uses it and when

- 입력 중 오타나 삭제 실수를 복구하려는 모든 사용자
- 잘라내기, 붙여넣기, 대량 삭제 직후 결과를 확인하고 되돌리려는 사용자
- 직전 undo 결과를 다시 적용하며 수정 방향을 탐색하는 사용자

### MVP relevance

- 우선순위: P0
- 메모 입력, 저장, 닫기 전에 반드시 제공되어야 하는 기본 편집 기능이다.
- 구현은 시스템 편집기 기본 동작을 최대한 활용하되, 제품 문서에서는 창별 독립성과 IME 안전성만 명확히 보장하면 된다.

### Confirmed requirements

- 사용자는 실행 취소를 할 수 있다.
- 사용자는 다시 실행을 할 수 있다.
- undo/redo는 텍스트 편집 변경에 대해서만 동작한다.
- 편집 히스토리는 문서 창별로 독립적으로 유지된다.
- undo/redo는 현재 활성 창에만 적용된다.
- 되돌릴 항목이나 다시 실행할 항목이 없어도 앱은 안정적으로 유지된다.

### Assumptions to keep MVP narrow

- 다중 단계 히스토리 UI 목록은 제공하지 않는다.
- 편집 이력의 영구 저장이나 앱 재시작 후 복원은 제공하지 않는다.
- 서식 편집, 이미지, 첨부 객체 같은 rich text 요소는 다루지 않는다.
- 시스템 텍스트 컴포넌트가 제공하는 자연스러운 편집 그룹핑을 기본으로 사용하되, 붙여넣기 한 번은 하나의 undo 단위로 취급하는 수준까지만 보장한다.

## 5. Main User Flow and Interaction Model

### Flow A. 일반적인 실행 취소

1. 사용자가 현재 창에서 문자를 입력, 삭제, 잘라내기 또는 붙여넣기 한다.
2. 앱은 해당 변경을 현재 창의 편집 히스토리에 기록한다.
3. 사용자가 메뉴 또는 `Command+Z`로 `실행 취소`를 실행한다.
4. 앱은 현재 창에서 가장 최근 편집 단위를 직전 상태로 되돌린다.
5. 텍스트 화면, 커서 위치, 선택 상태는 되돌린 결과에 맞게 갱신된다.
6. 되돌린 변경은 현재 창의 redo 가능 항목으로 이동한다.

### Flow B. 다시 실행

1. 사용자가 하나 이상의 undo를 수행한다.
2. 사용자가 메뉴 또는 `Shift+Command+Z`로 `다시 실행`을 실행한다.
3. 앱은 가장 최근에 undo된 편집 단위를 현재 창에 다시 적용한다.
4. 텍스트 화면, 커서 위치, 선택 상태는 재적용 결과에 맞게 갱신된다.

### Flow C. undo 이후 새 편집 발생

1. 사용자가 한 번 이상 undo를 수행해 redo 가능한 상태가 된다.
2. 사용자가 다시 입력, 삭제, 붙여넣기 같은 새 편집을 수행한다.
3. 앱은 새 편집을 현재 히스토리의 새 분기로 취급한다.
4. 기존 redo 가능 항목은 폐기된다.
5. 이후 `다시 실행`은 방금 폐기된 이전 분기를 복구하지 않는다.

### Flow D. 다중 창 독립 동작

1. 사용자가 두 개 이상의 문서 창을 열어 각각 편집한다.
2. 각 창은 자신의 텍스트 상태와 undo/redo 히스토리를 독립적으로 유지한다.
3. 사용자가 A 창에서 undo를 실행해도 B 창의 텍스트와 히스토리는 변하지 않는다.
4. 창 전환 후 다시 돌아와도 원래 창의 undo/redo 가능 상태는 유지된다.

### Flow E. IME 조합 중 편집 복구

1. 사용자가 한글 입력기 조합 중인 상태에서 텍스트를 입력한다.
2. 앱은 조합 중간 상태와 확정된 입력을 안전하게 다룬다.
3. undo/redo는 조합 문자를 깨뜨리거나 중복 삽입하지 않는 방식으로 동작해야 한다.
4. 조합 중인 텍스트는 확정 단위와 복구 단위가 충돌하지 않아야 한다.

## 6. Inputs, Outputs, and States

### Inputs

- 키보드 문자 입력
- 삭제, 개행, 범위 선택 후 대체 입력
- 잘라내기
- 붙여넣기
- `실행 취소`
- `다시 실행`
- 창 전환
- IME 조합 확정

### Outputs

- 되돌려진 텍스트 상태
- 다시 적용된 텍스트 상태
- 현재 창의 undo 가능 여부
- 현재 창의 redo 가능 여부
- 저장 여부 재판단이 반영된 문서 상태

### History session fields

- `windowId`: 창 독립성을 보장하기 위한 세션 식별자
- `undoAvailable`: 현재 창에서 undo 가능한지 여부
- `redoAvailable`: 현재 창에서 redo 가능한지 여부
- `lastCommittedTextState`: 가장 최근 확정된 텍스트 스냅샷 또는 편집 단위 기준 상태
- `hasUnsavedChanges`: 현재 텍스트가 마지막 저장 상태와 다른지 여부
- `isIMEComposing`: 현재 창이 입력기 조합 중인지 여부

### State definitions

| 상태           | 설명                                               | 진입 조건                           | 종료 조건                        |
| -------------- | -------------------------------------------------- | ----------------------------------- | -------------------------------- |
| undo 가능 상태 | 현재 창에 되돌릴 편집 단위가 하나 이상 있음        | 첫 편집 확정 후                     | 모든 히스토리를 되돌림           |
| undo 불가 상태 | 현재 창에 되돌릴 편집 단위가 없음                  | 새 빈 문서 직후 또는 최종 undo 완료 | 새 편집 확정                     |
| redo 가능 상태 | 직전에 undo된 편집 단위가 하나 이상 있음           | undo 수행 후                        | redo 모두 수행 또는 새 편집 발생 |
| redo 불가 상태 | 다시 적용할 편집 단위가 없음                       | 기본 상태                           | undo 수행                        |
| 조합 입력 상태 | IME 조합 중으로 히스토리 확정 단위가 안정되지 않음 | 한글 입력기 조합 시작               | 조합 확정 또는 취소              |

## 7. Business Rules

- undo/redo는 현재 활성 문서 창에만 적용된다.
- 한 창의 undo/redo 히스토리는 다른 창과 공유되지 않는다.
- 저장 여부와 관계없이 편집 이력은 현재 세션의 텍스트 변경 흐름을 따른다.
- undo 이후 새로운 편집이 발생하면 기존 redo 히스토리는 폐기된다.
- 붙여넣기 한 번은 사용자가 체감하기에 하나의 편집 단위로 되돌릴 수 있어야 한다.
- 잘라내기와 범위 대체 입력도 텍스트 변경으로 간주해 undo/redo 대상에 포함한다.
- 단순 커서 이동, 포커스 이동, 스크롤 같은 비텍스트 변경은 undo/redo 대상에 포함하지 않는다.
- undo/redo 결과로 현재 텍스트가 마지막 저장 상태와 같아지면 문서는 저장 완료 상태로 되돌아갈 수 있다.
- 반대로 redo 또는 새 편집으로 저장 상태와 다시 달라지면 문서는 미저장 상태가 된다.
- 시스템 메뉴의 `실행 취소`와 `다시 실행` 활성화 상태는 현재 창의 가능 여부와 일치해야 한다.

## 8. Validation and Error Handling

- 되돌릴 항목이 없을 때 앱이 종료되거나 오류를 내면 안 된다.
- 다시 실행할 항목이 없을 때 앱이 오류를 내면 안 된다.
- undo/redo 중 앱이 다른 창의 텍스트 상태를 건드리면 안 된다.
- 한글 입력기 조합 중인 텍스트가 undo/redo 과정에서 깨지거나 중복 입력되면 안 된다.
- 긴 텍스트 붙여넣기 후 undo 시 과도한 지연으로 앱이 멈춘 것처럼 보이면 안 된다.
- undo/redo 후 문서의 미저장 표시와 실제 저장 상태 판단이 어긋나면 안 된다.

## 9. Edge Cases and Resolved Decisions

### Edge cases

- 빈 문서에서 `실행 취소`를 반복 입력해도 아무 변화 없이 안정적으로 무시되어야 한다.
- 여러 차례 undo한 뒤 새 문자를 입력하면 이전 redo 경로는 복구되지 않아야 한다.
- 선택 영역 전체를 다른 텍스트로 바꾼 경우도 한 번의 편집 단위로 자연스럽게 되돌릴 수 있어야 한다.
- 매우 긴 한 줄 텍스트나 대량 붙여넣기에서도 undo/redo가 비정상적으로 느려지지 않아야 한다.
- 창을 전환한 뒤 다시 돌아와도 원래 창의 히스토리와 메뉴 활성화 상태가 유지되어야 한다.

### Resolved decisions

- undo/redo는 텍스트 변경만 다루고, 보기 옵션 변경이나 창 포커스 이동은 포함하지 않는다.
- undo 이후 새 편집이 발생하면 redo 히스토리는 폐기한다.
- 붙여넣기 한 번은 하나의 편집 단위로 취급한다.
- 히스토리는 창별로만 유지하며 문서 간 공유나 세션 복원은 하지 않는다.

## 10. Product Implications and Dependencies

- [Feature 01. 즉시 입력 가능한 다중 문서 창](./feature-01-instant-note-entry.md)의 `창 하나 = 문서 세션 하나` 모델이 선행되어야 한다.
- [Feature 03. `.txt` 저장과 다른 이름으로 저장](./feature-03-txt-save.md)의 저장 완료 상태와 현재 텍스트 상태를 비교해 undo/redo 후 미저장 표시를 다시 판단해야 한다.
- [Feature 04. 닫기 시 저장 확인 플로우](./feature-04-close-confirmation.md)는 undo/redo 결과로 달라진 최종 텍스트와 미저장 여부를 기준으로 종료 분기를 결정해야 한다.
- [Feature 06. Auto word wrap](./feature-06-auto-word-wrap.md)의 보기 변경은 undo/redo 대상이 아니어야 한다.
- 구현적으로는 시스템 편집기 기본 undo manager를 활용하는 방식이 MVP에 가장 단순하지만, 문서상 보장 대상은 창별 히스토리 분리와 사용자 체감 일관성이다.

## 11. Recommendation and Next Decision

### Recommendation

MVP에서는 시스템 편집기의 기본 undo/redo 메커니즘을 최대한 활용하되, 제품 규칙은 `현재 활성 창 기준`, `텍스트 변경만 대상`, `undo 뒤 새 편집 시 redo 폐기`, `저장 상태 재판단` 네 가지로 고정하는 것이 적절하다. 이 네 규칙만 명확하면 구현은 단순하게 유지하면서도 사용자 기대와 일치하는 동작을 만들 수 있다.

### Next decisions

1. IME 조합 중 입력을 하나의 undo 단위로 어디까지 묶을지 QA 기준을 정의한다.
2. 메뉴 비활성화 상태를 시스템 기본값에 맡길지, 앱 상태와 명시적으로 동기화할지 결정한다.

## 12. MVP Acceptance Criteria

- 사용자는 현재 창에서 발생한 텍스트 편집 변경을 `Command+Z`로 되돌릴 수 있다.
- 사용자는 직전에 undo한 변경을 `Shift+Command+Z`로 다시 적용할 수 있다.
- undo/redo는 현재 활성 창에만 적용되며 다른 창의 텍스트에는 영향을 주지 않는다.
- undo 이후 새 편집이 발생하면 기존 redo 항목은 사라진다.
- 붙여넣기 한 번은 사용자가 한 번의 undo로 되돌릴 수 있다.
- 되돌릴 항목이나 다시 실행할 항목이 없을 때도 앱은 오류 없이 유지된다.
- undo/redo 결과에 따라 문서의 미저장 상태와 제목 표시가 올바르게 갱신된다.
- 한글 입력기 조합이 포함된 편집에서도 텍스트가 깨지거나 중복 입력되지 않는다.

## 13. Out of Scope

- 다중 단계 편집 히스토리 시각화
- 히스토리 검색, 특정 시점 점프, 타임라인 UI
- 문서 간 편집 이력 공유
- 앱 재시작 후 undo/redo 이력 복원
- 텍스트 외 속성 변경을 포함한 범용 실행 취소 시스템
