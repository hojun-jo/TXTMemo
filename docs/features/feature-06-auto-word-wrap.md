# Feature 06. Auto word wrap

## 1. Idea Summary

사용자가 현재 문서 창의 표시 레이아웃을 `wrap 켜짐`과 `wrap 꺼짐` 사이에서 전환할 수 있게 하는 보기 기능이다. 이 기능은 텍스트 버퍼와 저장될 plain text 내용을 바꾸지 않고, 현재 창에서 긴 줄을 읽고 편집하는 방식을 조절하는 데만 집중한다.

## 2. Problem This Feature Solves

- 긴 문장이 많은 메모는 줄 감싸기가 없으면 읽고 수정하기 어렵다.
- 반대로 로그, URL, JSON 조각, 공백 없는 긴 문자열은 wrap이 항상 켜져 있으면 실제 한 줄 구조를 파악하기 어렵다.
- plain text 편집기는 문서 내용과 보기 옵션을 분리해야 한다.
- 여러 문서 창을 병렬로 쓰는 환경에서는 창마다 다른 보기 레이아웃을 선택할 수 있어야 한다.

## 3. Target User and Usage Context

- 회의 메모나 긴 문장 위주의 텍스트를 좁은 창에서 읽고 수정하는 사용자
- 로그, 식별자, 긴 URL 같은 한 줄 데이터를 원래 구조 그대로 확인하려는 사용자
- 여러 문서 창을 열어 두고 창마다 다른 너비와 다른 읽기 방식을 쓰는 사용자
- 저장 형식은 plain text로 유지하면서 화면 표시 방식만 바꾸고 싶은 macOS 사용자

## 4. Feature Concept Definition

### Feature name

Auto word wrap

### One-sentence definition

현재 활성 문서 창의 텍스트를 창 너비 기준으로 자동 줄바꿈해 보여주거나, 실제 개행 문자 기준의 원래 줄 구조대로 보여주는 창별 보기 전환 기능이다.

### Why it matters

- 메모장 앱은 `빠르게 읽고 바로 수정`하는 경험이 중요하므로 긴 줄 표시 방식 선택권이 필요하다.
- 저장되는 파일과 화면에 보이는 레이아웃이 섞이면 plain text 편집기의 신뢰성이 떨어진다.
- 다중 창 편집 환경에서는 보기 옵션도 문서 창 단위로 분리되어야 이후 저장, 닫기, undo/redo 규칙이 단순해진다.

### Who uses it and when

- 긴 설명 문장을 작성하거나 읽을 때 wrap을 켜려는 사용자
- 로그나 데이터 문자열의 실제 줄 경계를 확인하려고 wrap을 끄는 사용자
- 창 크기를 자주 바꾸면서 같은 텍스트를 다른 폭에서 읽는 사용자
- 저장 직전 또는 복사 직전에 문서 구조를 다시 확인하려는 사용자

### MVP relevance

- MVP 포함 권장 기능이다.
- 저장과 종료 같은 데이터 안전 기능보다는 후순위지만, 긴 줄 편집 경험과 plain text 성격 유지에 직접 영향을 준다.
- 이 기능은 구현 난이도보다 동작 규칙 정의가 더 중요하며, 특히 `보기 상태와 문서 상태의 분리`를 명확히 고정해야 한다.

### Confirmed requirements

- 사용자는 auto word wrap을 켤 수 있다.
- 사용자는 auto word wrap을 끌 수 있다.
- 메뉴와 툴바에서 현재 창의 wrap 상태를 전환할 수 있다.
- wrap 상태는 현재 활성 문서 창에만 적용된다.
- wrap 상태는 다른 문서 창과 독립적으로 유지된다.
- wrap 토글 직후 현재 창의 레이아웃은 즉시 갱신된다.
- wrap 상태 변경은 저장되는 `.txt` 내용, 실제 줄바꿈 문자, 파일 바이트를 바꾸지 않는다.
- wrap 상태 변경만으로 문서를 미저장 상태로 만들면 안 된다.
- wrap 상태 변경은 undo/redo 대상 텍스트 변경으로 취급하지 않는다.

### Assumptions to keep MVP narrow

- MVP에서는 `켜짐/꺼짐` 2단계만 제공하고, wrap 기준 열 수 설정은 제공하지 않는다.
- 새 문서 창은 기본적으로 wrap 켜짐 상태로 시작한다.
- wrap 상태는 현재 창이 살아 있는 동안만 유지되며, 저장 파일 메타데이터나 앱 재실행 복원 정보로 저장하지 않는다.
- wrap 꺼짐 상태에서 화면 폭을 넘는 긴 줄은 시스템 기본 비감싸기 표시 방식으로 다루며, 필요 시 수평 이동이 가능해야 한다.

## 5. Main User Flow and Interaction Model

### Flow A. wrap 켜기

1. 사용자가 현재 창에서 긴 줄이 포함된 문서를 보고 있다.
2. 사용자가 메뉴 또는 툴바에서 auto word wrap 켜기 액션을 실행한다.
3. 앱은 현재 창의 표시 모드를 `wrap 켜짐`으로 전환한다.
4. 편집 영역은 현재 창 너비와 현재 글자 크기를 기준으로 시각적 줄 배치를 다시 계산한다.
5. 텍스트 내용, 실제 개행 문자, 저장 상태는 그대로 유지된다.
6. 사용자는 같은 문서를 더 읽기 쉬운 형태로 계속 편집한다.

### Flow B. wrap 끄기

1. 사용자가 현재 창에서 auto word wrap 끄기 액션을 실행한다.
2. 앱은 현재 창의 표시 모드를 `wrap 꺼짐`으로 전환한다.
3. 실제 개행 문자가 없는 긴 줄은 인위적으로 감싸지지 않고 하나의 논리적 줄로 유지된다.
4. 커서 위치와 선택 범위는 같은 텍스트 인덱스를 기준으로 유지된다.
5. 사용자는 원래 줄 구조를 확인하거나 복사할 수 있다.

### Flow C. wrap 켜짐 상태에서 창 크기 또는 글자 크기 변경

1. 사용자가 현재 창 크기를 조절하거나 글자 크기를 바꾼다.
2. 앱은 현재 창이 wrap 켜짐 상태인지 확인한다.
3. wrap이 켜져 있으면 현재 폭과 글자 크기에 맞춰 시각적 줄 배치를 다시 계산한다.
4. 텍스트 내용, 실제 줄 수, 저장 상태는 변하지 않는다.
5. 사용자는 같은 문서를 새로운 표시 폭에 맞춰 계속 읽는다.

### Flow D. 다중 창 독립 동작

1. 사용자가 두 개 이상의 문서 창을 열어 둔다.
2. 각 창은 자신의 wrap 상태와 창 너비를 독립적으로 가진다.
3. 사용자가 A 창에서 wrap을 끄더라도 B 창의 레이아웃은 그대로 유지된다.
4. 창 전환 시 메뉴 체크 상태와 툴바 표시도 활성 창 기준으로 바뀐다.

### Flow E. wrap만 바꾼 뒤 저장 또는 닫기

1. 사용자가 텍스트는 수정하지 않고 wrap 상태만 바꾼다.
2. 사용자가 저장 또는 창 닫기를 시도한다.
3. 앱은 wrap 토글만으로는 미저장 변경이 발생하지 않은 것으로 판단한다.
4. 저장 파일 내용은 변경되지 않고, 닫기 확인도 텍스트 변경 여부만 기준으로 판단한다.

## 6. Inputs, Outputs, and States

### Inputs

- auto word wrap 켜기 액션
- auto word wrap 끄기 액션
- 창 크기 변경
- 글자 크기 변경
- 현재 창 전환
- 텍스트 입력과 편집
- 저장 및 닫기 시도

### Outputs

- 현재 창에 반영된 wrapped 또는 unwrapped 레이아웃
- 현재 창의 wrap 활성화 여부
- 활성 창 기준 메뉴 체크 상태와 툴바 상태
- wrap 토글 이후에도 유지되는 텍스트 내용, 커서 위치, 선택 범위
- wrap 여부와 무관하게 유지되는 문서 저장 상태

### Window view session fields

- `windowId`: 창 독립성을 보장하기 위한 식별자
- `isWrapEnabled`: 현재 창의 wrap 켜짐 여부
- `textContent`: 현재 문서의 실제 plain text 내용
- `hasUnsavedChanges`: 마지막 저장 이후 텍스트가 달라졌는지 여부
- `fontSize`: 현재 창 레이아웃 계산에 쓰이는 글자 크기
- `viewportWidth`: 현재 창의 편집 가능 폭
- `isFocused`: 현재 창이 활성 편집 창인지 여부

### State definitions

| 상태                 | 설명                                                                      | 진입 조건                        | 종료 조건                          |
| -------------------- | ------------------------------------------------------------------------- | -------------------------------- | ---------------------------------- |
| wrap 켜짐 상태       | 현재 창 폭과 글자 크기에 따라 긴 줄이 시각적으로 감싸져 보임              | wrap 켜기 실행 또는 기본값 적용  | wrap 끄기 실행                     |
| wrap 꺼짐 상태       | 실제 개행 문자만 줄 경계로 사용하고 인위적 줄 감싸기를 하지 않음          | wrap 끄기 실행                   | wrap 켜기 실행                     |
| 레이아웃 재계산 상태 | wrap 상태를 유지한 채 창 폭 또는 글자 크기 변화에 맞춰 표시를 다시 계산함 | 창 크기 변경 또는 글자 크기 변경 | 재계산 완료                        |

## 7. Business Rules

- auto word wrap은 보기 옵션이며 문서 내용 변경 기능이 아니다.
- wrap 토글은 현재 활성 문서 창에만 적용된다.
- 한 창의 wrap 상태는 다른 창과 공유되지 않는다.
- wrap 토글만으로는 `hasUnsavedChanges`가 `true`로 바뀌지 않는다.
- wrap 토글은 실제 줄바꿈 문자 추가, 삭제, 치환을 발생시키지 않는다.
- wrap 토글은 저장 파일의 인코딩, 바이트, 파일명, 저장 경로를 바꾸지 않는다.
- wrap 토글은 undo/redo 대상이 아니며, 텍스트 편집 히스토리를 오염시키지 않는다.
- wrap 켜짐 상태에서는 창 폭이나 글자 크기 변화가 생길 때마다 시각적 줄 배치를 다시 계산해야 한다.
- wrap 꺼짐 상태에서는 실제 개행 문자로만 줄이 구분되어야 한다.
- 활성 창이 바뀌면 메뉴 체크 상태와 툴바 상태는 그 창의 wrap 상태와 일치해야 한다.
- 새 문서 창은 기본적으로 wrap 켜짐 상태로 시작하지만, 이후 각 창은 독립적으로 토글될 수 있다.

## 8. Validation and Error Handling

- wrap 토글 직후 텍스트가 사라지거나 손상되면 안 된다.
- wrap 토글 중 커서 위치나 선택 범위가 엉뚱한 위치로 이동하면 안 된다.
- 매우 긴 한 줄 텍스트에서도 토글 직후 앱이 멈추거나 비정상 종료되면 안 된다.
- 공백이 거의 없는 긴 문자열도 가능한 범위에서 안정적으로 표시돼야 한다.
- 한글 입력기 조합 중 wrap을 바꿔도 조합 문자가 깨지거나 중복 입력되면 안 된다.
- wrap 상태를 바꿔도 저장과 닫기 플로우의 미저장 판정이 왜곡되면 안 된다.
- wrap을 바꾼 뒤 undo를 실행했을 때 마지막 텍스트 편집이 되돌려져야 하며, wrap 상태는 그대로 유지돼야 한다.

## 9. Edge Cases and Resolved Decisions

### Edge cases

- 창 너비를 매우 좁게 줄인 상태에서도 wrap 켜짐 레이아웃은 가능한 범위에서 안정적으로 유지되어야 한다.
- 매우 긴 URL, base64 문자열, 공백 없는 식별자는 wrap 켜짐 상태에서도 앱을 멈추게 하면 안 된다.
- wrap 꺼짐 상태에서 화면을 넘는 긴 줄은 잘리지 않고 사용자가 확인 가능한 방식으로 접근돼야 한다.
- 글자 크기를 크게 키운 뒤 wrap을 켜거나 끌 때도 텍스트 내용과 저장 상태는 그대로 유지돼야 한다.
- 여러 창이 서로 다른 폭을 가진 상태에서도 각 창은 자기 폭 기준으로만 레이아웃을 계산해야 한다.
- wrap만 바꾸고 바로 닫을 때는 텍스트 변경이 없으면 저장 확인이 뜨지 않아야 한다.

### Resolved decisions

- auto word wrap은 파일 내용이 아닌 창별 보기 상태로 정의한다.
- wrap 토글은 미저장 변경으로 간주하지 않는다.
- wrap 토글은 undo/redo 히스토리에 포함하지 않는다.
- 새 문서 창의 기본값은 wrap 켜짐으로 둔다.
- wrap 상태는 문서 저장 메타데이터나 재실행 복원 정보로 저장하지 않는다.

## 10. Product Implications and Dependencies

- [Feature 01. 즉시 입력 가능한 다중 문서 창](./feature-01-instant-note-entry.md)의 `창 하나 = 문서 세션 하나` 모델이 선행되어야 한다.
- [Feature 02. 글자 크기 조절](./feature-02-text-size-control.md)은 wrap 켜짐 상태의 시각적 줄 배치에 직접 영향을 준다.
- [Feature 03. `.txt` 저장과 다른 이름으로 저장](./feature-03-txt-save.md)은 wrap 상태와 무관하게 실제 텍스트만 저장해야 한다.
- [Feature 04. 닫기 시 저장 확인 플로우](./feature-04-close-confirmation.md)는 wrap 토글만으로는 미저장 변경이 발생하지 않는다는 규칙을 사용해야 한다.
- [Feature 05. Undo/Redo](./feature-05-undo-redo.md)는 wrap 토글을 복구 대상에 포함하지 않아야 한다.
- 구현 관점에서는 `wrap 켜짐/꺼짐`을 실시간 전환하고 비감싸기 긴 줄을 안정적으로 표시할 수 있는 편집 컴포넌트가 필요하다.
- SwiftUI 기본 편집 컴포넌트만으로 비감싸기 모드 제어가 제한된다면, AppKit 기반 텍스트 뷰 브리징 여부를 검토해야 한다.

## 11. Recommendation and Next Decision

### Recommendation

MVP에서는 auto word wrap을 `현재 창에만 적용되는 보기 토글`로 고정하는 것이 적절하다. 이때 핵심 규칙은 `텍스트 내용 불변`, `창별 독립`, `미저장 상태 비영향`, `undo/redo 비포함` 네 가지다. 이 규칙만 분명하면 사용자 기대와 plain text 편집기의 성격을 모두 지킬 수 있다.

### Next decisions

1. wrap 꺼짐 상태에서 수평 이동 경험을 스크롤바 중심으로 둘지, 트랙패드 제스처 중심으로 둘지 UI 정책을 확정한다.
2. 현재 창 기본값만 둘지, 장기적으로 앱 전체 기본 wrap 선호값을 설정으로 노출할지 결정한다.

## 12. MVP Acceptance Criteria

- 사용자는 메뉴 또는 툴바에서 현재 창의 auto word wrap을 켜고 끌 수 있다.
- wrap 토글 직후 현재 창의 레이아웃이 즉시 갱신된다.
- wrap 상태를 바꿔도 실제 텍스트 내용과 저장되는 `.txt` 파일 내용은 바뀌지 않는다.
- wrap 상태를 바꿔도 문서는 미저장 상태로 바뀌지 않는다.
- wrap 상태를 바꿔도 닫기 확인 플로우는 텍스트 변경 여부만 기준으로 동작한다.
- 한 창의 wrap 변경은 다른 창의 레이아웃과 상태에 영향을 주지 않는다.
- 창 크기나 글자 크기가 바뀌면 wrap 켜짐 상태의 레이아웃은 현재 폭 기준으로 다시 계산된다.
- wrap을 바꾼 뒤 undo/redo를 실행하면 마지막 텍스트 변경만 대상으로 동작한다.
- 매우 긴 한 줄 텍스트에서도 토글 동작이 앱을 멈추게 하지 않는다.

## 13. Out of Scope

- 특정 열 수 기준의 고정 wrap 폭 설정
- 파일별 wrap 선호값 저장
- 앱 재실행 후 wrap 상태 세션 복원
- 줄 번호, 상태바, 문단 서식 같은 별도 편집 보기 기능
