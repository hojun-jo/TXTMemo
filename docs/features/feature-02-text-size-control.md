# Feature 02. 글자 크기 조절

## 1. Idea Summary

사용자가 현재 활성 문서 창의 plain text 편집 가독성을 위해 글자 크기를 즉시 확대, 축소, 기본값 복원할 수 있게 하는 기능이다. 이 기능은 문서 내용이나 파일 포맷을 바꾸지 않고 보기 크기만 조절하며, 현재 창에서 조정한 크기는 그 창 세션에만 적용된다. 앱은 별도로 기본 글자 크기 설정을 저장하고, 새 문서 창이나 기존 파일을 다시 열 때는 항상 이 앱 기본 글자 크기로 시작한다.

## 2. Problem This Feature Solves

- plain text 메모라도 읽기 편해야 실제 사용 빈도가 올라간다.
- macOS 환경은 모니터 크기와 해상도 편차가 커서 기본 글자 크기 하나로 모든 사용자 경험을 만족시키기 어렵다.
- 단순한 메모장일수록 내용 편집을 방해하지 않는 최소한의 개인화 수단이 필요하다.
- 보기 크기 조절이 없으면 빠른 메모라는 장점이 있어도 장시간 읽기와 수정 단계에서 피로가 커진다.

## 3. Target User and Usage Context

- 작은 기본 글자 크기에서 바로 피로를 느끼는 사용자
- 고해상도 외부 모니터와 노트북 화면을 오가며 메모를 작성하는 사용자
- 긴 회의 메모나 로그 조각을 읽으면서 동시에 수정해야 하는 사용자
- 문서 포맷은 건드리지 않고 화면 가독성만 조절하고 싶은 사용자

## 4. Feature Concept Definition

### Feature name

글자 크기 조절

### One-sentence definition

현재 활성 문서 창의 편집기 글자 크기를 즉시 변경하고, 앱 설정에 저장된 기본 글자 크기를 새 문서 창과 재오픈 문서의 초기 보기 크기로 사용하는 기능이다.

### Why it matters

- 메모장 앱은 빠르게 쓰는 도구일 뿐 아니라 빠르게 읽고 고치는 도구이기도 하다.
- 글자 크기 조절은 복잡한 스타일 시스템 없이도 가독성 문제를 가장 저렴하게 해결한다.
- 저장 파일이 plain text라는 원칙을 유지하면서도 사용자 체감 품질을 높일 수 있다.

### Who uses it and when

- 앱 실행 직후 기본 글자 크기가 작거나 크게 느껴지는 사용자
- 문서를 읽다가 확대가 필요해지는 사용자
- 새 문서를 열기 전에 앱 전역 기본 글자 크기를 조정하고 싶은 사용자

### MVP relevance

- 우선순위: P1
- 핵심 입력 기능 다음으로 빠르게 체감되는 편집 편의 기능이다.
- 저장, 닫기, undo/redo보다 구현 난도는 낮지만, 실제 일상 사용성에는 직접적인 영향을 준다.

### Confirmed requirements

- 사용자는 글자 크기를 축소할 수 있다.
- 사용자는 글자 크기를 확대할 수 있다.
- 사용자는 기본 크기로 되돌릴 수 있다.
- 툴바에는 현재 글자 크기 pt 값이 항상 노출되며, 사용자는 숫자 입력으로 직접 현재 창 크기를 조절할 수 있다.
- 사용자는 키보드 단축키로 글자 크기를 확대, 축소, 기본값 복원할 수 있다.
- 변경은 현재 활성 편집 창에 즉시 반영된다.
- 앱 설정에서 기본 글자 크기를 수정하고 저장할 수 있다.
- 앱 또는 파일을 다시 열면 현재 창의 마지막 임시 크기가 아니라 앱 기본 글자 크기로 시작한다.

### Assumptions to keep MVP narrow

- 현재 창의 글자 크기 변경 단위는 1pt다.
- 조절 결과는 현재 활성 창에 즉시 반영된다.
- 현재 창에서 바꾼 크기는 앱 기본 글자 크기를 자동으로 바꾸지 않는다.
- 앱 기본 글자 크기의 초기값은 14pt다.
- 앱 설정에서 바꾼 기본 글자 크기는 앱 재실행 후에도 유지된다.
- 이미 열려 있는 다른 창의 글자 크기는 자동으로 동기화하지 않는다.
- 새 문서 창과 재오픈 문서는 앱 설정에 저장된 기본 글자 크기를 초기값으로 사용한다.
- 툴바의 글자 크기 조절 영역은 `A-`, 항상 노출되는 현재 pt 입력 필드, `A+` 구성을 사용하고, 기본값 복원은 메뉴와 단축키에서도 제공한다.

## 5. Main User Flow and Interaction Model

### Flow A. 현재 창에서 글자 크기 확대 또는 축소

1. 사용자가 현재 문서 창에서 메모를 작성하거나 읽고 있다.
2. 사용자가 툴바, 메뉴, 또는 키보드 단축키에서 확대 또는 축소 액션을 선택한다.
3. 앱은 현재 글자 크기에 1pt를 더하거나 빼되, 8pt 미만 또는 72pt 초과로는 이동하지 않는다.
4. 현재 활성 창의 편집 영역 폰트 크기가 즉시 갱신된다.
5. 앱 기본 글자 크기 설정은 변경되지 않는다.
6. 사용자는 텍스트 내용 변경 없이 같은 문서를 계속 읽거나 작성한다.

### Flow B. 툴바 숫자 입력으로 현재 창 직접 조절

1. 사용자가 툴바에 항상 노출되는 현재 pt 입력 필드를 선택한다.
2. 사용자가 원하는 글자 크기 정수를 입력하고 `Enter` 또는 포커스 이탈로 값을 확정한다.
3. 앱은 입력값을 정수 pt 값으로 해석한다.
4. 입력값이 8pt 미만이면 8pt로, 72pt 초과면 72pt로 보정한다.
5. 입력값이 비어 있거나 숫자로 해석할 수 없으면 변경을 적용하지 않고 직전 유효 값을 다시 표시한다.
6. 유효한 값이 확정되면 현재 활성 창의 편집 영역 폰트 크기를 즉시 갱신한다.
7. 앱 기본 글자 크기 설정은 변경되지 않는다.

### Flow C. 앱 설정에서 기본 글자 크기 변경

1. 사용자가 앱 설정을 연다.
2. 사용자가 기본 글자 크기 값을 확인하고 수정한다.
3. 앱은 입력값을 8pt에서 72pt 사이 정수 값으로 검증하고 저장한다.
4. 저장된 값은 앱 기본 글자 크기가 된다.
5. 이미 열려 있는 창은 자신의 현재 보기 크기를 유지한다.
6. 이후 새 문서 창, 앱 재실행 후 첫 창, 기존 파일 재오픈은 저장된 앱 기본 글자 크기로 시작한다.

### Flow D. 기본값 복원

1. 사용자가 메뉴 또는 `Command+0` 단축키로 기본값 복원 액션을 선택한다.
2. 앱은 현재 활성 창의 글자 크기를 현재 앱 기본 글자 크기로 바꾼다.
3. 앱 기본 글자 크기 자체는 바뀌지 않는다.
4. 사용자는 앱이 정의한 기본 보기 밀도로 계속 편집한다.

### Flow E. 앱 재실행, 새 문서 창 생성, 기존 파일 재오픈

1. 앱이 실행되거나 사용자가 새 문서 창을 열거나 기존 `.txt` 파일을 다시 연다.
2. 앱은 저장된 기본 글자 크기 설정을 읽는다.
3. 저장된 값이 유효하면 새 편집 창 초기 크기로 적용한다.
4. 저장된 값이 없거나 손상되었으면 14pt를 기본값으로 사용한다.
5. 이전 세션에서 해당 창이나 파일에 임시로 적용했던 글자 크기는 복원하지 않는다.

### Flow F. 여러 창이 열린 상태에서의 동작

1. 사용자가 두 개 이상의 문서 창을 열어둔다.
2. 한 창에서 글자 크기를 변경하면 그 창만 즉시 갱신된다.
3. 다른 이미 열려 있는 창은 자신의 현재 보기 크기를 유지한다.
4. 앱 설정에서 기본 글자 크기를 바꿔도 이미 열린 창들은 즉시 동기화되지 않는다.
5. 이후 새로 여는 창과 재오픈 문서는 새 앱 기본 글자 크기를 초기값으로 사용한다.

## 6. Inputs, Outputs, and States

### Inputs

- 확대 액션
- 축소 액션
- 기본값 복원 액션
- 확대 단축키 `Command++`
- 축소 단축키 `Command+-`
- 기본값 복원 단축키 `Command+0`
- 툴바 현재 pt 입력 필드의 숫자 입력
- 앱 설정의 기본 글자 크기 입력
- `Enter` 또는 포커스 이탈에 따른 숫자 입력 확정
- 앱 실행
- 새 문서 창 생성
- 기존 `.txt` 파일 재오픈
- 저장된 설정 로드 결과

### Outputs

- 현재 활성 창 편집기의 글자 크기
- 앱 설정에 저장된 기본 글자 크기
- 툴바에 항상 노출되는 현재 크기 입력값
- 앱 설정 화면에 표시되는 기본 글자 크기 값
- 글자 크기 변경에 따라 재계산된 편집기 레이아웃

### View preference fields

- `currentWindowFontSize`: 현재 활성 창에 적용된 글자 크기
- `appDefaultFontSize`: 앱 설정에 저장된 기본 글자 크기
- `toolbarFontSizeFieldValue`: 툴바 입력 필드에 표시되는 현재 글자 크기 값
- `settingsDefaultFontSizeFieldValue`: 앱 설정 입력 필드에 표시되는 기본 글자 크기 값
- `initialDefaultFontSize`: 초기 기본값 14pt
- `minFontSize`: 최소값 8pt
- `maxFontSize`: 최대값 72pt
- `fontStepSize`: 증감 단위 1pt
- `isAtMinFontSize`: 현재 창이 최소값 상태인지 여부
- `isAtMaxFontSize`: 현재 창이 최대값 상태인지 여부

| 설정 복구 상태           | 설정값이 없거나 손상되어 14pt로 대체됨           | 설정 로드 실패                | 유효한 기본값 저장 성공 |

## 7. Business Rules

- 앱 기본 글자 크기의 초기값은 14pt다.
- 최소 글자 크기는 8pt다.
- 최대 글자 크기는 72pt다.
- 글자 크기 변경 단위는 1pt다.
- 확대 단축키는 `Command++`다.
- 축소 단축키는 `Command+-`다.
- 기본값 복원 단축키는 `Command+0`다.
- 툴바에는 현재 글자 크기 pt 값을 표시하는 숫자 입력 필드가 항상 노출된다.
- 사용자는 툴바 입력 필드에 정수 pt 값을 직접 입력해 현재 활성 창의 글자 크기를 변경할 수 있다.
- 앱 설정에서는 기본 글자 크기를 8pt에서 72pt 사이 정수 값으로 저장할 수 있다.
- 숫자 입력 확정 시 값이 8pt 미만이면 8pt로, 72pt 초과면 72pt로 보정한다.
- 숫자 입력이 비어 있거나 숫자로 해석할 수 없으면 적용하지 않고 직전 유효 값으로 복구한다.
- 글자 크기 변경은 현재 활성 창의 보기 상태에만 즉시 영향을 준다.
- 현재 창에서 글자 크기를 바꿔도 앱 기본 글자 크기는 자동으로 바뀌지 않는다.
- 단축키 입력도 현재 활성 창에만 적용된다.
- 기본값 복원은 현재 활성 창을 현재 앱 기본 글자 크기로 되돌린다.
- 앱 설정에서 바꾼 기본 글자 크기는 앱 재실행 후에도 유지된다.
- 새 문서 창과 기존 파일 재오픈은 앱 설정에 저장된 기본 글자 크기를 사용한다.
- 이미 열려 있는 다른 창의 글자 크기는 자동으로 업데이트하지 않는다.
- 앱 또는 파일 재오픈 시 현재 창의 마지막 임시 글자 크기는 복원하지 않는다.
- 글자 크기 변경은 문서 텍스트, 저장 경로, 미저장 상태를 바꾸지 않는다.
- 저장되는 `.txt` 파일에는 글자 크기 메타데이터를 쓰지 않는다.
- 설정값이 없거나 손상되었으면 안전하게 14pt로 되돌린다.

## 8. Validation and Error Handling

- 최소값보다 더 작은 값으로 내려가지 않아야 한다.
- 최대값보다 더 큰 값으로 올라가지 않아야 한다.
- 툴바 또는 앱 설정의 숫자 입력 필드에 범위 밖 값이 입력되면 가장 가까운 허용 값으로 보정되어야 한다.
- 숫자 입력 필드에 빈 값이나 비숫자 문자가 입력되어도 앱이 실패하지 않고 직전 유효 값으로 복구되어야 한다.
- 단축키 입력이 텍스트 편집 입력으로 오인되어 본문에 삽입되면 안 된다.
- 크기 변경 중 입력 중인 텍스트, 선택 영역, 커서 위치가 비정상적으로 손실되면 안 된다.
- 앱 재실행 후 저장된 앱 기본 글자 크기가 정상 복원돼야 한다.
- 기존 파일을 다시 열 때 마지막 임시 크기가 아니라 앱 기본 글자 크기가 적용돼야 한다.
- 설정값이 손상되어도 앱이 실패하지 않고 14pt로 안전하게 시작해야 한다.
- 긴 문서에서도 크기 변경 후 스크롤 위치가 과도하게 튀지 않아야 한다.
- 한글 입력기 조합 중 글자 크기를 바꿔도 조합 상태가 깨지지 않아야 한다.

## 9. Edge Cases and Resolved Decisions

### Edge cases

- 최소값에서 축소를 다시 눌러도 값은 8pt로 유지되어야 한다.
- 최대값에서 확대를 다시 눌러도 값은 72pt로 유지되어야 한다.
- 빈 새 문서도 현재 앱 기본 글자 크기를 그대로 적용받아야 한다.
- 서로 다른 글자 크기를 가진 여러 창이 동시에 열린 상태에서도 창 전환 시 각 창의 표시 크기가 유지되어야 한다.
- auto word wrap 켜짐 또는 꺼짐 상태에서도 크기 변경은 정상적으로 레이아웃을 재계산해야 한다.
- 앱 설정에서 기본 글자 크기를 바꾼 직후에도 이미 열려 있는 창은 현재 크기를 유지해야 한다.
- 숫자 입력 필드가 비워진 채 포커스를 잃으면 직전 유효 값이 다시 표시되어야 한다.

### Resolved decisions

- 툴바에는 현재 글자 크기 pt 값을 항상 노출한다.
- 사용자는 툴바 숫자 입력 필드에 직접 값을 입력해 현재 창 글자 크기를 조절할 수 있다.
- 글자 크기 조절 단축키는 확대 `Command++`, 축소 `Command+-`, 기본값 복원 `Command+0`를 사용한다.
- 앱 또는 파일을 다시 열 때는 현재 창의 마지막 임시 크기가 아니라 앱 기본 글자 크기를 사용한다.

## 10. Product Implications and Dependencies

- [Feature 01. 즉시 입력 가능한 다중 문서 창](./feature-01-instant-note-entry.md)의 창별 편집 뷰가 글자 크기 상태를 반영해야 한다.
- [Feature 01. 즉시 입력 가능한 다중 문서 창](./feature-01-instant-note-entry.md)의 기존 파일 열기 플로우와 결합될 때도 재오픈 문서는 동일한 앱 기본 글자 크기 규칙을 따라야 한다.
- [Feature 06. Auto word wrap](./feature-06-auto-word-wrap.md)가 적용된 상태에서도 글자 크기 조절은 동일하게 레이아웃 계산을 유발한다.
- 앱 설정 저장소가 필요하며, 설정 로드 실패 시 안전한 기본값 복구 경로가 필요하다.
- `.txt` 저장 기능과는 보기 상태 분리 원칙을 유지해야 한다.

## 11. Recommendation and Next Decision

### Recommendation

MVP에서는 `현재 창 조절은 세션성`, `앱 설정은 기본값 저장`, `재오픈 시에는 항상 앱 기본값 사용`이라는 세 규칙을 고정하는 것이 가장 단순하다. 이 방식은 다중 창의 독립성을 유지하면서도, 사용자가 원하는 시작 가독성을 앱 전역에서 통제하게 한다.

### Next decisions

현재 문서 범위에서 추가 결정 사항은 없다.

## 12. MVP Acceptance Criteria

- 사용자는 현재 활성 창의 글자 크기를 즉시 확대, 축소, 기본값 복원할 수 있다.
- 툴바에는 현재 글자 크기 pt 값이 항상 표시되며, 사용자는 숫자를 직접 입력해 현재 창 크기를 조절할 수 있다.
- 사용자는 `Command++`, `Command+-`, `Command+0` 단축키로도 글자 크기를 즉시 조절할 수 있다.
- 글자 크기는 8pt에서 72pt 사이를 1pt 단위로만 이동한다.
- 앱 설정에서 기본 글자 크기를 수정하고 저장할 수 있다.
- `Command+0` 기본값 복원은 현재 창을 앱 설정의 기본 글자 크기로 되돌린다.
- 앱 재실행, 새 문서 창 생성, 기존 파일 재오픈 시에는 앱 기본 글자 크기가 적용된다.
- 현재 창에서 임시로 조정한 글자 크기는 앱 또는 파일 재오픈 시 복원되지 않는다.
- 이미 열려 있는 다른 창은 자동으로 같은 크기로 바뀌지 않는다.
- 글자 크기 변경은 문서 텍스트 내용과 저장 파일 내용에 영향을 주지 않는다.
- 설정값이 없거나 손상된 경우 앱은 14pt로 안전하게 시작한다.
