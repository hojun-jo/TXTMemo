# Feature 03. `.txt` 저장과 다른 이름으로 저장

## 1. Idea Summary

이 기능은 현재 문서 창의 plain text 내용을 사용자가 원하는 위치에 UTF-8 기반 `.txt` 파일로 저장하고, 필요하면 새 파일명과 새 위치로 다시 저장할 수 있게 하는 파일 출력 기능이다. macOS 메모장 MVP에서 이 기능은 `입력한 내용을 실제 파일로 남길 수 있는가`를 결정하는 핵심 기준이며, 닫기 시 저장 확인 플로우의 실행 기반이기도 하다.

### Feature Name

`.txt` 저장 및 다른 이름으로 저장

### One-sentence Definition

활성 문서 창의 현재 텍스트를 UTF-8 `.txt` 파일로 저장하거나, 새 경로를 선택해 현재 문서의 저장 대상을 갱신하는 기능이다.

## 2. Problem This Feature Solves

- 메모장 앱은 작성만 가능하고 파일 저장이 안 되면 사용자의 작업 결과를 보존하지 못한다.
- 사용자는 임시 메모, 회의 기록, 코드 조각, 로그 메모를 가장 호환성 높은 형식인 `.txt`로 남기길 기대한다.
- 종료 직전 `저장`, `다른 이름으로 저장` 선택지가 있으려면 그 저장 동작이 먼저 명확히 정의돼야 한다.
- 여러 문서 창을 동시에 사용하는 상황에서도 어떤 창이 어느 파일에 저장되는지 혼동이 없어야 한다.

## 3. Target User And Usage Context

### Who Uses It

- 빠르게 메모를 적고 파일로 남기려는 macOS 사용자
- plain text로 결과를 저장해 다른 앱, 메신저, 개발 툴로 전달하려는 사용자
- 여러 문서 창을 분리해 초안과 최종본을 따로 저장하려는 사용자

### When It Is Used

- 작성한 메모를 처음으로 파일로 보존하려 할 때
- 이미 저장한 문서를 같은 파일로 다시 갱신할 때
- 현재 메모를 다른 이름의 새 파일로 분기 저장할 때
- 닫기 시 저장 확인 창에서 저장 분기를 선택했을 때

## 4. Feature Concept Definition

### Why It Matters

이 기능이 있어야 앱이 단순 입력 도구가 아니라 실제 문서 작성 도구로 성립한다. 또한 MVP의 사용자 성공 기준인 `1분 안에 메모 입력과 저장 완료`를 직접 뒷받침한다.

### Confirmed Requirements

- `저장` 액션을 제공한다.
- `다른 이름으로 저장` 액션을 제공한다.
- 저장 형식은 UTF-8 `.txt`다.
- 저장 성공 후 현재 문서는 저장 완료 상태가 된다.
- 저장 경로와 저장 상태는 문서 창별로 독립적으로 유지된다.

### Assumptions

- macOS 기본 저장 패널 동작을 최대한 따른다.
- 별도 포맷 선택 UI 없이 `.txt` 중심 저장만 지원한다.
- 다른 이름으로 저장은 새 문서를 복제하지 않고 현재 문서의 저장 경로 자체를 새 위치로 갱신한다.

### Entry Points

- 메뉴의 `저장`
- 툴바의 `저장` 버튼
- 메뉴의 `다른 이름으로 저장`
- 단축키 `Command+S`
- 단축키 `Shift+Command+S`
- 닫기 확인 창의 `저장`
- 닫기 확인 창의 `다른 이름으로 저장`

## 5. MVP Relevance And Priority

### Priority

P0, 필수 기능

### Why It Is In MVP

- 저장이 없으면 메모장 앱의 결과물이 외부에 남지 않는다.
- 닫기 시 저장 확인 플로우는 이 기능 없이는 완결되지 않는다.
- 파일 열기, 최근 파일, 자동 저장보다 먼저 필요한 가장 작은 파일 시스템 연동 기능이다.

### Not Included In This MVP Slice

- 최근 파일 목록
- 자동 저장
- 여러 파일 형식 내보내기
- 충돌 해결, 버전 비교, 복구 히스토리

## 6. Main User Flow And Interaction Model

### Flow A. 처음 저장

1. 사용자가 새 문서에서 내용을 입력한다.
2. 사용자가 `저장`을 실행한다.
3. 현재 문서에 저장 경로가 없으므로 앱은 저장 패널을 연다.
4. 사용자가 파일명과 저장 위치를 선택한다.
5. 앱은 현재 텍스트를 UTF-8 `.txt` 파일로 기록한다.
6. 저장 성공 시 현재 문서는 저장 완료 상태가 되고, 선택한 경로가 현재 문서의 파일 경로가 된다.

### Flow B. 이미 저장된 문서 다시 저장

1. 사용자가 기존에 저장한 문서를 계속 수정한다.
2. 사용자가 `저장`을 실행한다.
3. 현재 문서에 저장 경로가 있으므로 앱은 저장 패널 없이 같은 파일에 덮어쓴다.
4. 저장 성공 시 현재 문서는 저장 완료 상태로 돌아간다.

### Flow C. 다른 이름으로 저장

1. 사용자가 현재 문서를 새 파일명이나 새 위치로 분기하고 싶다.
2. 사용자가 `다른 이름으로 저장`을 실행한다.
3. 앱은 현재 경로 유무와 관계없이 항상 저장 패널을 연다.
4. 사용자가 새 파일명과 위치를 선택한다.
5. 앱은 현재 텍스트를 새 경로에 저장한다.
6. 저장 성공 시 현재 문서는 새 경로를 현재 파일 경로로 사용한다.

### Flow D. 닫기 시 저장 연동

1. 사용자가 창 닫기 또는 앱 종료를 시도한다.
2. 닫기 확인 플로우에서 `저장` 또는 `다른 이름으로 저장`을 선택한다.
3. 이 기능이 저장을 수행한다.
4. 저장 성공 시 닫기 플로우가 종료를 계속 진행하고, 저장 취소 또는 실패 시 종료를 중단한다.

## 7. Inputs, Outputs, And States

### Required Inputs Or Conditions

- 현재 문서 텍스트
- 저장 액션 유형: `저장` 또는 `다른 이름으로 저장`
- 현재 문서의 기존 저장 경로 유무
- 사용자가 선택한 파일명과 저장 위치
- 파일 시스템 쓰기 권한이 유효해야 함

### Expected Outputs Or System Responses

- 디스크에 생성되거나 갱신된 UTF-8 `.txt` 파일
- 현재 문서에 연결된 최신 파일 경로
- 현재 문서의 미저장 상태 해제
- 닫기 플로우에서 호출된 경우 종료 진행 가능 상태
- 저장 실패 시 사용자에게 보이는 오류 피드백

### Document States

| 상태                          | 설명                                     | 저장 액션 결과                              |
| ----------------------------- | ---------------------------------------- | ------------------------------------------- |
| 새 문서, 저장 경로 없음       | 아직 파일과 연결되지 않은 문서           | `저장` 시 저장 패널 표시                    |
| 저장된 문서, 변경 없음        | 현재 내용이 디스크와 동일함              | `저장` 가능하나 실질적으로 동일 내용 재기록 |
| 저장된 문서, 미저장 변경 있음 | 기존 파일 경로는 있으나 수정이 남아 있음 | `저장` 시 같은 파일 덮어쓰기                |
| 저장 패널 표시 중             | 사용자 입력 대기 상태                    | 저장 또는 취소를 기다림                     |
| 저장 실패 상태                | 쓰기 실패 또는 권한 실패 발생            | 오류 표시 후 편집 상태 유지                 |

### State Rules

- 저장 성공 직후 문서는 `저장 완료` 상태가 된다.
- 저장 패널 취소는 상태를 변경하지 않는다.
- 다른 이름으로 저장 성공 후 현재 문서는 새 파일 경로에 연결된다.
- 여러 문서 창이 열려 있어도 상태 전이는 활성 창 기준으로만 일어난다.

## 8. Business Rules And Failure Handling

### Business Rules

- 저장 인코딩은 UTF-8 고정이다.
- 저장 결과 파일 형식은 항상 `.txt`다.
- `저장`은 저장 경로가 있으면 같은 파일에 덮어쓴다.
- `저장`은 저장 경로가 없으면 저장 패널을 연다.
- `다른 이름으로 저장`은 항상 저장 패널을 연다.
- 사용자가 확장자를 지정하지 않으면 `.txt`를 기본 제안한다.
- 사용자가 다른 확장자를 직접 입력해도 최종 저장 파일명은 `.txt`로 정규화한다.
- 저장 후 현재 문서는 방금 저장한 경로를 현재 파일 경로로 사용한다.
- 활성 창만 저장 액션의 대상이 된다.

### Validation And Error Handling

- 저장 패널을 취소하면 현재 편집 상태를 그대로 유지한다.
- 저장 실패 시 단순 alert로 오류를 보여주고 문서를 닫지 않는다.
- 권한 문제, 경로 문제, 디스크 쓰기 실패가 발생하면 재시도 가능 상태를 유지한다.
- 동일 파일명 덮어쓰기 여부는 시스템 저장 패널의 기본 확인 동작을 따른다.

### Failure Cases, Exceptions, Or Ambiguities

- 빈 문서도 사용자가 명시적으로 저장하려 하면 저장할 수 있어야 한다.
- 한글 입력 조합 중 저장 시 조합 중 텍스트가 누락되지 않아야 한다.
- 저장은 성공했지만 후속 종료 단계가 실패하는 경우, 파일은 이미 저장된 것으로 간주해야 한다.

## 9. Edge Cases, Dependencies, And Product Implications

### Edge Cases

- 여러 문서 창이 열린 상태에서는 활성 창만 저장해야 한다.
- 다른 이름으로 저장 후에도 문서 내용은 그대로 유지되고 현재 경로만 새 파일로 갱신돼야 한다.
- 기존 파일의 내용을 모두 지운 빈 문서도 사용자가 명시적으로 저장하면 빈 `.txt` 파일로 저장될 수 있어야 한다.
- 같은 세션에서 한 문서를 여러 번 다른 이름으로 저장해도 히스토리 목록을 제공할 필요는 없다.

### Dependencies

- [Feature 01. 즉시 입력 가능한 메모 창](./feature-01-instant-note-entry.md)의 현재 텍스트 상태를 읽어야 한다.
- [Feature 04. 닫기 시 저장 확인 플로우](./feature-04-close-confirmation.md)에서 저장 분기를 호출한다.

### Product Implications

- 저장 성공 여부는 문서의 미저장 표시와 창 상태 갱신에 직접 연결된다.
- 기존 `.txt` 파일 열기 플로우도 동일한 문서 경로 모델을 재사용하게 된다.
- 저장 동작이 흔들리면 종료 플로우 신뢰도까지 함께 떨어지므로, MVP에서 안정성을 우선 검증해야 한다.

## 10. Resolved Decisions And Recommendation

### Resolved Decisions

- 저장 파일 형식은 `.txt`로 고정한다.
- 사용자가 확장자를 입력하지 않으면 `.txt`를 자동 부여한다.
- 사용자가 다른 확장자를 직접 입력해도 최종 저장 결과는 `.txt`로 정규화한다.
- UTF-8 저장은 BOM 없는 방식으로 정의한다.
- 저장 실패 피드백은 단순 alert로 처리한다.

### BOM Note

BOM은 Byte Order Mark의 약자이며, 텍스트 파일 맨 앞에 붙는 특수 바이트 표식이다. UTF-8에서는 필수 요소가 아니고, 일부 도구에서는 이 표식이 불필요한 문자나 호환성 차이로 이어질 수 있다. 따라서 이 MVP에서는 `UTF-8 without BOM`을 기준으로 두는 편이 plain text 메모장 용도에 더 단순하고 예측 가능하다.

### Recommendation

MVP에서는 macOS 기본 저장 패널을 사용하고, 저장 형식과 확장자를 모두 `.txt`로 고정하는 현재 결정이 적절하다. 또한 저장 실패 시 단순 alert를 보여준 뒤 편집 상태를 유지하는 방식이 구현 범위를 작게 유지하면서도 사용자에게 충분히 명확하다.

### Next Decision

현재 문서 기준으로 핵심 오픈 질문은 해소됐다. 다음 단계에서는 alert 문구 수준과 `.txt` 정규화가 저장 패널 UI에서 어떻게 보일지만 구현 상세로 정리하면 된다.
