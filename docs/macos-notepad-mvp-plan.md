# macOS 메모장 앱 MVP 기획서

## 1. Product Summary

AppKit 기반의 macOS용 초경량 메모장 앱이다. 사용자는 앱을 실행하면 별도 설정이나 초기 화면 없이 곧바로 빈 문서에서 타이핑을 시작할 수 있고, 필요할 때 새 문서를 추가로 열거나 기존 `.txt` 파일을 별도 창으로 열어 여러 문서 창을 독립적으로 사용할 수 있다. 또한 글자 크기 조절, undo/redo, auto word wrap 같은 기본 편집 편의 기능을 유지한 채 내용을 `.txt` 파일로 저장할 수 있으며, 종료 시에는 Windows 메모장과 유사하게 저장 여부를 직접 선택할 수 있게 하되 내용이 공백, 탭, 줄바꿈만 있는 경우에는 확인 창 없이 바로 종료하는 흐름에 집중한다.

## 2. Target Users

- 아이디어, 임시 메모, 로그 조각을 빠르게 적고 저장하려는 macOS 사용자
- 서식 없는 plain text 편집기를 선호하는 개발자, 기획자, 사무직 사용자
- 메모 앱이나 워드 프로세서보다 더 단순하고 즉시 반응하는 편집기를 원하는 사용자
- `txt` 파일로 바로 남기고 다른 도구로 전달하려는 사용자

## 3. Problem Statement

macOS에는 메모 작성 도구가 많지만, `실행하면 바로 쓸 수 있는 단순한 plain text 메모장` 경험은 의외로 분산되어 있다. 사용자는 문서 생성, 포맷 설정, 복잡한 UI를 거치지 않고 곧바로 입력을 시작하고 싶어 하며, 종료 직전에는 데이터 손실 없이 저장 여부를 분명하게 결정하고 싶어 한다.

## 4. MVP Goal

- 사용자는 앱 실행 직후 추가 클릭 없이 바로 타이핑을 시작할 수 있다.
- 사용자는 새 문서를 추가로 열어 여러 문서 창을 독립적으로 사용할 수 있다.
- 사용자는 Finder 또는 파일 열기로 기존 `.txt` 파일을 독립적인 문서 창으로 열 수 있다.
- 사용자는 현재 문서의 글자 크기를 읽기 편한 수준으로 즉시 조절할 수 있다.
- 사용자는 앱 설정에서 기본 글자 크기를 수정할 수 있고, 앱 또는 파일을 다시 열면 현재 창의 임시 크기가 아니라 앱 기본 글자 크기로 시작한다.
- 사용자는 편집 중 undo/redo로 직전 변경을 되돌리거나 다시 적용할 수 있다.
- 사용자는 auto word wrap을 켜고 끄며 현재 창의 텍스트 레이아웃을 조절할 수 있다.
- 사용자는 문서를 UTF-8 기반 `.txt` 파일로 저장하거나 다른 이름으로 저장할 수 있다.
- 사용자는 닫기 시 `저장`, `다른 이름으로 저장`, `취소`, `저장하지 않고 종료` 중 하나를 선택할 수 있다.
- 사용자는 창 제목 옆의 `*` 표시로 현재 문서의 미저장 상태를 바로 인지할 수 있다.
- 빈 문서는 확인 창 없이 즉시 종료된다.
- 초기 성공 신호: 첫 실행 사용자가 1분 안에 메모 입력과 `.txt` 저장을 완료할 수 있다.

## 5. Core User Scenarios

1. 사용자는 앱을 실행하자마자 빈 문서에서 커서를 보고 바로 메모를 입력한다.
2. 사용자는 새 문서를 추가로 열어 첫 번째 메모는 그대로 둔 채 다른 내용을 별도 창에서 독립적으로 작성한다.
3. 사용자는 Finder 또는 파일 열기로 기존 `.txt` 파일을 새 창에서 열고 내용을 이어서 수정한다.
4. 사용자는 작은 글씨가 불편해 툴바에서 글자 크기를 키우고 계속 작성하되, 다음 실행이나 파일 재오픈에서는 앱 기본 글자 크기로 시작한다.
5. 사용자는 필요하면 앱 설정에서 기본 글자 크기를 바꿔 이후 새 문서 창과 재오픈 문서의 시작 크기를 조정한다.
6. 사용자는 실수로 지운 문장을 undo/redo로 되돌리거나 다시 적용한다.
7. 사용자는 긴 줄이 화면 밖으로 나갈 때 auto word wrap을 켜거나 끄며 읽기 편한 배치를 선택한다.
8. 사용자는 작성한 내용을 `meeting-notes.txt` 같은 파일명으로 저장한다.
9. 사용자는 창 제목 옆의 `*` 표시로 미저장 상태를 확인하고, 저장하지 않은 메모를 닫으려 할 때 상황에 맞게 저장하거나 다른 이름으로 저장하거나 취소하거나 저장 없이 종료한다.
10. 사용자는 내용이 공백, 탭, 줄바꿈만 있는 문서를 닫을 때 별도 확인 없이 바로 앱을 종료한다.

## 6. Detailed MVP Feature List

### Feature 1. 즉시 입력 가능한 다중 문서 창

**Why it matters**

앱의 핵심 가치가 `실행 즉시 작성`이기 때문이다. 첫 화면이 느리거나 커서 포커스가 없으면 메모장으로서의 존재 이유가 약해지며, 필요할 때 문서를 하나 더 열 수 없다면 Windows 메모장과 유사한 문서 작업 흐름도 성립하지 않는다.

**Main user flow**

1. 사용자가 앱을 실행한다.
2. 앱은 빈 plain text 문서 1개를 연다.
3. 텍스트 편집 영역에 자동으로 포커스를 둔다.
4. 사용자는 바로 키보드 입력이나 붙여넣기를 수행한다.
5. 문서가 수정되면 현재 문서는 미저장 상태로 전환된다.
6. 사용자가 새 문서를 열면 새로운 빈 문서 창이 추가로 열리고 각 창은 독립적으로 편집된다.
7. 사용자가 Finder 또는 파일 열기로 기존 `.txt` 파일을 열면 해당 파일은 자신의 문서 창에서 독립적으로 열린다.

**Inputs and outputs**

- 입력: 키보드 입력, 붙여넣기된 plain text, 새 문서 생성 액션, 기존 `.txt` 파일 열기 액션, 닫기 의도 전까지의 편집 액션
- 출력: 화면에 표시되는 현재 문서 내용, 문서의 미저장 상태, 현재 문서 제목 상태, 열린 문서 창별 편집 상태, 파일에서 로드된 기존 문서 내용

**Edge cases or failure cases**

- 한글 입력기 조합 중에도 텍스트가 깨지지 않아야 한다.
- 서식이 있는 텍스트를 붙여넣어도 plain text만 유지해야 한다.
- 공백, 탭, 줄바꿈만 있는 내용은 `빈 문서`로 간주한다.
- 매우 긴 텍스트 입력은 지원하되, 대용량 파일 최적화는 MVP 범위에서 제외한다.
- 한 창에서 편집 중이어도 다른 창의 내용이나 미저장 상태에 영향을 주면 안 된다.

**Acceptance criteria**

- 앱 실행 후 사용자는 별도 클릭 없이 바로 텍스트를 입력할 수 있다.
- 편집 영역은 plain text만 표시한다.
- 입력 또는 붙여넣기 후 현재 문서 내용이 즉시 반영된다.
- 사용자가 내용을 변경하면 문서는 미저장 상태로 전환된다.
- 사용자는 새 문서를 추가로 열어 여러 문서 창을 독립적으로 사용할 수 있다.
- 사용자는 Finder 또는 파일 열기로 기존 `.txt` 파일을 별도 창에서 열 수 있다.

### Feature 2. 글자 크기 조절

**Why it matters**

메모장 앱은 긴 시간을 쓰지 않더라도 즉시 읽기 편해야 한다. 글자 크기 조절은 시력, 모니터 해상도, 작성 상황 차이를 가장 저렴하게 흡수하는 기능이다.

**Main user flow**

1. 사용자가 메모를 작성 중이다.
2. 툴바, 메뉴, 단축키, 또는 앱 설정에서 글자 크기 관련 액션을 선택한다.
3. 편집 영역의 글자 크기가 즉시 변경된다.
4. 사용자는 변경된 크기로 계속 작성한다.

**Inputs and outputs**

- 입력: 확대, 축소, 기본값 복원 액션 또는 해당 단축키, 앱 설정의 기본 글자 크기 수정
- 출력: 편집 영역에 반영된 새 글자 크기, 현재 크기 표시 상태, 앱에 저장된 기본 글자 크기

**Edge cases or failure cases**

- 최소 크기 아래로 더 줄이려 하면 더 이상 감소하지 않아야 한다.
- 최대 크기 위로 더 키우려 하면 더 이상 증가하지 않아야 한다.
- 글자 크기 변경은 문서 내용 자체를 바꾸지 않아야 한다.
- 저장된 `.txt` 파일에는 글자 크기 정보가 포함되지 않는다는 점을 UI에서 혼동시키지 않아야 한다.

**Acceptance criteria**

- 사용자는 작성 중인 문서의 글자 크기를 즉시 조절할 수 있다.
- 사용자는 `Command++`, `Command+-`, `Command+0` 단축키로도 글자 크기를 조절할 수 있다.
- 글자 크기는 최소 8pt, 최대 72pt 범위에서 동작한다.
- 기본 글자 크기는 초기값 14pt이며 앱 설정에서 수정할 수 있다.
- 현재 창에서 조절한 글자 크기는 앱 또는 파일 재오픈 시 유지되지 않고 앱 기본 글자 크기로 시작한다.
- 글자 크기 변경은 저장된 텍스트 내용에 영향을 주지 않는다.

### Feature 3. `.txt` 저장 및 다른 이름으로 저장

**Why it matters**

이 앱은 노트 보관 서비스가 아니라 plain text 작성 도구다. 따라서 사용자가 현재 내용을 파일로 남길 수 있어야 MVP가 완성된다.

**Main user flow**

1. 사용자가 메뉴 또는 단축키로 `저장`을 실행한다.
2. 현재 문서에 저장 경로가 없으면 저장 패널을 연다.
3. 사용자가 파일명과 저장 위치를 선택하고 저장한다.
4. 앱은 내용을 UTF-8 `.txt` 파일로 저장하고 문서를 저장 완료 상태로 전환한다.
5. 사용자가 `다른 이름으로 저장`을 실행하면 항상 저장 패널을 다시 연다.

**Inputs and outputs**

- 입력: 현재 문서 텍스트, 파일명, 저장 경로, 저장 또는 다른 이름으로 저장 액션
- 출력: 저장된 `.txt` 파일, 현재 문서의 저장 경로, 저장 완료 상태

**Edge cases or failure cases**

- 사용자가 저장 패널을 취소하면 문서는 열린 상태로 유지되어야 한다.
- 저장 권한이 없거나 디스크 쓰기에 실패하면 종료하지 않고 오류를 보여줘야 한다.
- 사용자가 확장자를 입력하지 않으면 `.txt`를 기본 제안해야 한다.
- 빈 문서도 사용자가 명시적으로 저장하려 하면 저장할 수 있어야 한다.

**Acceptance criteria**

- 사용자는 현재 문서를 `.txt` 파일로 저장할 수 있다.
- `저장`은 기존 저장 경로가 있으면 같은 파일에 덮어쓰고, 없으면 저장 패널을 연다.
- `다른 이름으로 저장`은 항상 저장 패널을 연다.
- 저장이 완료되면 현재 문서는 저장 완료 상태로 전환된다.
- 저장 취소 또는 실패 시 문서는 닫히지 않고 현재 편집 상태를 유지한다.

### Feature 4. 닫기 시 저장 확인 플로우

**Why it matters**

메모장의 종료 플로우는 데이터 손실을 막는 마지막 안전장치다. 동시에 빈 문서까지 매번 확인하면 핵심 가치인 속도가 떨어진다.

**Main user flow**

1. 사용자가 창 닫기 또는 앱 종료를 시도한다.
2. 앱은 현재 문서가 비어 있는지, 저장되지 않은 변경이 있는지를 판단한다.
3. 내용이 비어 있으면 즉시 종료한다.
4. 내용이 있고 저장되지 않은 변경이 있으면 `저장`, `다른 이름으로 저장`, `취소`, `저장하지 않고 종료` 4개 액션이 있는 확인 창을 표시한다.
5. 사용자가 하나를 선택하면 해당 분기로 처리한다.

**Inputs and outputs**

- 입력: 닫기 의도, 현재 문서 내용, 현재 저장 경로, 미저장 변경 여부, 사용자의 확인 창 선택
- 출력: 종료 여부, 저장된 파일, 편집 상태 유지 여부

**Edge cases or failure cases**

- `저장` 선택 후 저장 패널을 취소하면 종료하지 않고 편집기로 복귀해야 한다.
- `다른 이름으로 저장` 선택 후 저장 실패 시 종료하지 않아야 한다.
- 이미 저장된 파일이고 추가 수정이 없는 경우는 확인 창 없이 닫을 수 있어야 한다.
- 공백, 탭, 줄바꿈만 있는 문서는 `빈 내용`으로 고정해 간주해야 한다.

**Acceptance criteria**

- 내용이 비어 있는 문서는 닫기 시 확인 창 없이 즉시 종료된다.
- 내용이 있고 미저장 변경이 있으면 정확히 4개 선택지를 가진 확인 창이 표시된다.
- `저장`은 저장 성공 후 종료한다.
- `다른 이름으로 저장`은 새 경로로 저장 성공 후 종료한다.
- `취소`는 종료를 중단하고 현재 편집 상태를 유지한다.
- `저장하지 않고 종료`는 파일을 쓰지 않고 종료한다.

### Feature 5. Undo/Redo

**Why it matters**

간단한 메모장일수록 사용자는 실수를 바로 되돌릴 수 있기를 기대한다. undo/redo가 없으면 짧은 편집에서도 복사, 잘라내기, 삭제 같은 기본 액션의 리스크가 과도하게 커진다.

**Main user flow**

1. 사용자가 문서를 입력하거나 수정한다.
2. 사용자가 메뉴 또는 단축키로 `실행 취소`를 선택한다.
3. 앱은 가장 최근 텍스트 변경을 되돌린다.
4. 사용자가 `다시 실행`을 선택하면 직전에 되돌린 변경을 다시 적용한다.

**Inputs and outputs**

- 입력: 텍스트 편집 액션, `실행 취소`, `다시 실행`
- 출력: 되돌려진 또는 다시 적용된 텍스트 상태, 현재 창의 편집 히스토리 상태

**Edge cases or failure cases**

- 되돌릴 항목이 없을 때 앱이 오류를 내면 안 된다.
- 한글 입력기 조합 중의 편집 이력은 깨지지 않아야 한다.
- 여러 창이 열려 있어도 undo/redo 히스토리는 창별로 독립적이어야 한다.

**Acceptance criteria**

- 사용자는 텍스트 편집 변경에 대해 undo/redo를 사용할 수 있다.
- 되돌리기와 다시 실행은 현재 창의 편집 이력 순서를 일관되게 따른다.
- 한 창의 undo/redo 동작이 다른 창의 텍스트에 영향을 주지 않는다.

### Feature 6. Auto word wrap

**Why it matters**

plain text 편집기에서는 줄바꿈 규칙을 문서 내용과 분리해 다루는 것이 중요하다. auto word wrap이 없으면 긴 문장을 읽고 수정하기 어려워지고, 반대로 항상 강제되면 로그나 긴 한 줄 텍스트를 다루기 불편해진다.

**Main user flow**

1. 사용자가 긴 줄이 포함된 문서를 보고 있다.
2. 사용자가 메뉴 또는 툴바에서 auto word wrap을 켜거나 끈다.
3. 편집 영역은 현재 창 너비에 맞춰 줄을 감싸거나, 감싸지 않은 상태를 유지한다.
4. 사용자는 동일한 텍스트 내용을 다른 보기 상태로 계속 편집한다.

**Inputs and outputs**

- 입력: auto word wrap 켜기/끄기 액션
- 출력: 현재 창의 텍스트 레이아웃, wrap 적용 여부 상태

**Edge cases or failure cases**

- 매우 긴 한 줄 텍스트에서도 토글 직후 앱이 멈추면 안 된다.
- wrap 토글은 저장될 텍스트 내용이나 줄바꿈 문자 자체를 바꾸면 안 된다.
- 여러 창이 열려 있어도 wrap 상태는 창별로 독립적으로 반영돼야 한다.

**Acceptance criteria**

- 사용자는 auto word wrap을 켜고 끌 수 있다.
- 토글 직후 현재 창의 텍스트 레이아웃이 즉시 갱신된다.
- wrap 상태를 바꿔도 저장되는 plain text 내용은 바뀌지 않는다.
- 한 창의 wrap 토글이 다른 창의 레이아웃에 영향을 주지 않는다.

## 8. Open Questions or Assumptions

### Assumptions

- MVP는 앱 실행 시 빈 문서 1개를 기본으로 열고, 사용자는 필요할 때 새 문서를 추가로 열어 여러 창을 동시에 사용할 수 있다.
- 기존 `.txt` 파일은 Finder 또는 파일 열기 메뉴로 각자의 독립 창에서 열 수 있다.
- 저장 파일 인코딩은 UTF-8로 고정한다.
- 앱 설정에는 기본 글자 크기를 저장하며, 앱 재실행이나 파일 재오픈 시에는 항상 그 기본값을 사용한다.
- `저장`과 `다른 이름으로 저장`은 macOS 기본 메뉴와 단축키로 제공한다.
- 메뉴 외에 별도 `저장` 툴바 버튼은 제공하지 않는다.
- 내용이 공백, 탭, 줄바꿈만 있는 경우는 `빈 내용`으로 간주해 바로 종료한다.
- 창 제목에는 현재 파일명 또는 기본 문서명이 표시되며, 미저장 변경이 있으면 옆에 `*`를 함께 표시한다.
- 저장 여부 확인 창은 `내용이 있고 미저장 변경이 있을 때만` 표시한다.
- undo/redo는 macOS 기본 편집 히스토리와 단축키를 우선 활용한다.
- auto word wrap은 현재 창의 보기 상태에만 영향을 준다.
